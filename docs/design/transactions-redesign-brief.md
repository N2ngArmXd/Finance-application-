# Design Brief — หน้า "บันทึกรายการ" และ "ประวัติธุรกรรม"

> ให้ออกแบบ UI/UX ใหม่ของ 2 หน้าในแอปบันทึกรายรับรายจ่ายส่วนตัว (เว็บ responsive)
> โค้ดปัจจุบัน: `finance-frontend/src/components/TransactionPage.jsx`, `finance-frontend/src/components/HistoryPage.jsx`

---

## 1. บริบทผลิตภัณฑ์

- **ผลิตภัณฑ์**: เว็บแอปจัดการการเงินส่วนตัว (รายรับ/รายจ่าย, หมวดหมู่, ผ่อนชำระ, Dashboard)
- **ผู้ใช้**: คนทั่วไปที่จดรายจ่ายรายวัน — ใช้ทั้งมือถือ (จดระหว่างวัน) และ desktop (ย้อนดู/แก้ไข)
- **ภาษา UI**: ไทยทั้งหมด, สกุลเงินบาท (฿), วันที่ปฏิทินพุทธศักราช (เช่น 02/10/2569)
- **Stack**: React + Tailwind CSS v4 + lucide-react icons, SweetAlert2 (ใช้อยู่ — เปิดให้เสนอทางเลือกแทนได้)

## 2. เป้าหมายของงานนี้

1. **บันทึกให้เร็วที่สุด** — จดรายจ่าย 1 รายการได้ใน ≤ 3 การแตะ + พิมพ์ตัวเลข ไม่มี dialog ขวาง
2. **ประวัติอ่านง่ายเหมือนแอปธนาคาร** — กวาดตาแล้วรู้ว่าวันไหนใช้อะไรไปเท่าไร
3. **Mobile-first** — ทั้ง 2 หน้าต้องสวยที่ 375px โดยไม่มี horizontal scroll
4. **หน้าตาเป็นระบบเดียวกัน** — radius, spacing, ตัวเลข, การแจ้งเตือน ใช้ชุดเดียวกัน

## 5. หน้า A — บันทึกรายการ (TransactionPage)

### ปัจจุบัน
การ์ดเดียว กว้าง `max-w-xl`: toggle รายจ่าย/รายรับ → grid ไอคอนหมวด 4 คอลัมน์ → ช่องจำนวนเงินตัวใหญ่ → วันที่ (chip วันนี้/เมื่อวาน + date picker) → รายละเอียด → ปุ่มบันทึก → ใต้การ์ดมี "รายการล่าสุดวันนี้" 3 รายการ
กดบันทึกแล้ว **ขึ้น confirm dialog ทุกครั้ง** แล้วตามด้วย success modal อีกอัน

### ปัญหา
- 2 modal ต่อการบันทึก 1 ครั้ง = ช้าและน่ารำคาญ
- จำนวนเงินอยู่ล่างหมวด แต่คนมักรู้ตัวเลขก่อน
- ไม่แสดงยอดสุทธิของวันนี้ (มีข้อมูลแล้ว)
- ปุ่มบันทึกสี brand เสมอ ไม่บอกว่ากำลังบันทึกรับหรือจ่าย
- ไม่มีทางไปหน้าประวัติ / ไม่มีทางเพิ่มหมวดจากหน้านี้

### สิ่งที่ต้องการให้ออกแบบ
1. **ลำดับใหม่**: ประเภท → **จำนวนเงิน (autofocus, hero ของหน้า)** → หมวด → วันที่ → รายละเอียด
2. ช่องจำนวนเงินจัด format คอมมาระหว่างพิมพ์, สีตามประเภท (แดง/เขียว)
3. Grid หมวดแบบไอคอน + ชื่อ มีช่องสุดท้าย **"+ เพิ่มหมวด"**
4. หลังเลือกหมวด → แสดง **chip รายละเอียดที่เคยใช้บ่อยในหมวดนั้น** (เช่น `ข้าวเที่ยง` `กาแฟ`) กดเติมได้
5. **ไม่มี confirm** — บันทึกทันที แล้วขึ้น **toast "บันทึกแล้ว −฿120 · เลิกทำ"** (หายเองใน ~5 วิ)
6. หลังบันทึก: ล้างจำนวน/หมวด/รายละเอียด แต่**คงประเภทและวันที่**ไว้ (จดต่อเนื่องได้)
7. ปุ่มบันทึกสีตามประเภท; **มือถือให้ sticky ติดล่างจอ**
8. ส่วน "วันนี้": หัวแสดง **ยอดสุทธิวันนี้** + จำนวนรายการ, ลิสต์ 3–5 รายการล่าสุด, ลิงก์ "ดูทั้งหมด →"
9. รายการที่เพิ่งบันทึก animate เข้ามาในลิสต์ "วันนี้"

### States ที่ต้องมี
- default / กำลังโหลดหมวด (skeleton grid) / ยังไม่มีหมวดในประเภทนี้
- validation: จำนวนเงิน ≤ 0, ยังไม่เลือกหมวด → **inline error ใต้ช่อง** (ไม่ใช่ modal)
- กำลังบันทึก (ปุ่ม loading) / บันทึกล้มเหลว (toast error + ข้อมูลในฟอร์มยังอยู่)
- วันนี้ยังไม่มีรายการ (empty state ชวนบันทึก)

## 6. หน้า B — ประวัติธุรกรรม (HistoryPage)

### ปัจจุบัน
1. การ์ดค้นหา + ปุ่ม "ตัวกรอง" (เปิด panel: ประเภท segmented / หมวด dropdown / วันเริ่ม / วันสิ้นสุด)
2. การ์ดสรุป 3 ใบตัวใหญ่: รายรับรวม / รายจ่ายรวม / ยอดสุทธิ (gradient navy)
3. ตาราง 7 คอลัมน์: ☐ / รหัส / วันที่ / หมวด (pill) / รายละเอียด / จำนวนเงิน / ปุ่มแก้ไข+ลบ — sort ได้ที่วันที่และจำนวนเงิน
4. เลือกหลายรายการ → แถบ "เลือกแล้ว N รายการ · ลบ"
5. Pagination ตัวเลข 10 รายการ/หน้า
6. แก้ไข = SweetAlert modal (dropdown หมวดรวมทุกประเภท, จำนวน, รายละเอียด — **แก้วันที่ไม่ได้**)

### ปัญหา
- ตาราง 7 คอลัมน์บนมือถือต้อง scroll แนวนอน
- ไม่มีไอคอนหมวด อ่านยาก กวาดตาไม่ได้
- การ์ดสรุปกินพื้นที่ครึ่งจอ และไม่บอกว่ายอดเปลี่ยนตามตัวกรอง
- ปุ่มแก้ไข/ลบทุกแถวทำให้รก
- ตัวกรองที่เปิดอยู่มองไม่เห็นเมื่อปิด panel
- loading/empty เป็นแค่ข้อความ
- มีข้อความ debug `User ID : 1` โผล่ในหัวตาราง (ต้องเอาออก)

### สิ่งที่ต้องการให้ออกแบบ
1. **รายการจัดกลุ่มตามวัน** (หัวกลุ่ม: `พฤ. 2 ต.ค. 2569` + ยอดสุทธิของวันนั้นชิดขวา)
   แต่ละแถว: ไอคอนหมวด (วงกลมพื้นอ่อนสีตามหมวด) · รายละเอียด (บรรทัดหลัก) · หมวด + รหัส (บรรทัดรอง) · ยอดเงินชิดขวา (+เขียว / −แดง)
   - Desktop จะคงเป็นตารางก็ได้ แต่ขอเวอร์ชัน grouped list อย่างน้อยสำหรับ `< md`
2. **แถบสรุปแบบกระชับ** 1 แถว: รายรับ · รายจ่าย · สุทธิ พร้อม label "ตามตัวกรองที่เลือก" (อาจมี progress bar สัดส่วนรับ/จ่าย)
3. **ค้นหา + ตัวกรอง**
   - Quick date presets: `เดือนนี้` `เดือนก่อน` `30 วัน` `ปีนี้` `กำหนดเอง`
   - ประเภท: segmented ทั้งหมด/รายรับ/รายจ่าย
   - หมวด: เลือกจากไอคอน/chip (multi-select ถ้าทำได้)
   - **Active filter chips** ใต้ช่องค้นหา `[รายจ่าย ✕] [อาหาร ✕] [ต.ค. 2569 ✕]` + "ล้างทั้งหมด"
   - Sort: วันที่ใหม่→เก่า / เก่า→ใหม่ / ยอดมาก→น้อย / น้อย→มาก (dropdown เดียว)
4. **กดแถว → เปิด Detail drawer** (desktop: slide จากขวา / mobile: bottom sheet)
   - ดูรายละเอียดครบ + แก้ไขในที่ได้: ประเภท toggle, grid ไอคอนหมวด (กรองตามประเภท), จำนวน, **วันที่**, รายละเอียด
   - ปุ่ม "ลบรายการ" (danger, ล่างสุด)
   - ใช้ component ฟอร์มชุดเดียวกับหน้าบันทึก
5. **Multi-select**: desktop = checkbox ตอน hover / mobile = long-press เข้าโหมดเลือก → แถบ action ลอยด้านล่าง "เลือกแล้ว N · ลบ"
6. **ลบ**: ยังมี confirm (เพราะย้อนไม่ได้) แต่หลังลบใช้ toast แทน success modal
7. **Pagination**: เสนอได้ระหว่างเลขหน้า (เดิม) หรือ "โหลดเพิ่ม"/infinite scroll — ระบุเหตุผล

### States ที่ต้องมี
- loading (skeleton rows ตามรูปแบบแถวจริง)
- empty: ยังไม่มีรายการเลย (CTA → ไปบันทึก) / ไม่พบตามตัวกรอง (CTA → ล้างตัวกรอง)
- error โหลดไม่สำเร็จ (ปุ่มลองใหม่)
- โหมดเลือกหลายรายการ
- drawer: ดู / กำลังบันทึก / validation error
- ยอดสุทธิติดลบ (สีและข้อความ "ใช้เกินรายรับ")

## 8. ข้อจำกัด

- ใช้ Tailwind + token ข้างบน; ไอคอนใช้ lucide-react เท่านั้น
- ฟอนต์ต้องรองรับภาษาไทยดี (เสนอได้ เช่น IBM Plex Sans Thai / Noto Sans Thai / Anuphan)
- Light mode เป็นหลัก (dark mode = bonus)
- Accessibility: contrast ≥ 4.5:1 สำหรับข้อความ, touch target ≥ 44px, ไม่สื่อความหมายด้วยสีอย่างเดียว (มี +/− และไอคอน ↑↓ ประกอบ)
- ไม่ต้องแก้ backend — ใช้ข้อมูลตามข้อ 4 (ฟีเจอร์ที่ต้องการ API เพิ่ม เช่น "รายละเอียดที่ใช้บ่อย" ให้ระบุไว้)

## 9. สิ่งที่อยากได้กลับมา

1. Mockup หน้า A และหน้า B — **mobile (375px)** และ **desktop (1280px)**
2. หน้าจอ states สำคัญตามข้อ 5–6 (อย่างน้อย: empty, loading, drawer แก้ไข, โหมดเลือกหลายรายการ, toast)
3. Spec ของ component ในข้อ 7 (ขนาด, spacing, radius, สีแต่ละ state)
4. Radius / spacing / typography scale ที่สรุปแล้ว
5. หมายเหตุ interaction & animation (ระยะเวลา, easing) — มี `zoomIn` แบบเด้งเล็กน้อยใช้อยู่แล้ว
6. ถ้าเป็นไปได้ ขอเป็น HTML/React + Tailwind ที่ใช้ token ชุดนี้ เพื่อนำไปใส่โค้ดได้ตรง
