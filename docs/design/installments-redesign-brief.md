# Design Brief — หน้า "ตารางผ่อนชำระ" (Installments)

> ให้ออกแบบ UI ใหม่ของหน้าตารางผ่อนชำระ ให้เข้าชุดกับหน้า "บันทึกรายการ" และ "ประวัติธุรกรรม" ที่ redesign ไปแล้ว
> โค้ดปัจจุบัน: `finance-frontend/src/components/Installments.jsx`
> อ้างอิงงานรอบก่อน: `docs/design/transactions-redesign-brief.md` และโค้ดที่ทำเสร็จแล้วใน `TransactionPage.jsx`, `HistoryPage.jsx`, `TxnForm.jsx`, `TxnRow.jsx`, `components/ui/*`

---

## 0. ข้อกำหนดสำคัญ (อ่านก่อน)

- **ปรับแค่ UX/UI — flow, logic และ API ต้องเหมือนเดิมทั้งหมด**
  - ห้ามเพิ่มฟีเจอร์ที่ต้องแก้ backend
  - ยังมี dialog ยืนยันก่อน บันทึก / แก้ไข / จ่ายงวด / ยกเลิกจ่าย / ปิดยอด / ลบ (ปรับหน้าตาได้)
  - success modal หลังทำเสร็จ → เปลี่ยนเป็น toast ได้ (เหมือนหน้าอื่นที่ทำไปแล้ว)
- **ใช้ design system ชุดเดียวกับรอบก่อน** — ไม่สร้างสไตล์ใหม่ที่ไม่เข้าชุด
- Desktop เป็นหลัก (แอปมี sidebar คงที่ ยังไม่มี layout มือถือ) แต่ไม่ควรพังที่จอแคบ
- ไม่ต้องทำ bottom nav

## 1. Design system ที่ต้องใช้ต่อ (จากรอบก่อน)

- **ฟอนต์**: IBM Plex Sans Thai (ทั้งแอป) + IBM Plex Mono สำหรับรหัส/ตัวเลขเชิงเทคนิค · ยอดเงินใช้ `tabular-nums`, ทศนิยม 2 ตำแหน่ง, มีคอมมา
- **สี** (Tailwind token ใน `finance-frontend/src/index.css`): `brand` (navy) · `gold` · `income` (เขียว) · `expense` (แดงอิฐ) · `warn` (เหลืองอำพัน) · พื้น/ข้อความรอง `slate` (ข้อความรองใช้ slate-500 ขึ้นไป)
- **Radius**: chip = full · input / button / tile = 12 (`rounded-xl`) · card / toast = 16 (`rounded-2xl`) · sheet / dialog = 24 (`rounded-3xl`)
- **Type scale**: page-title 24/32 700 · section 16/24 600 · body 15/22 500 · label 14/20 600 · caption 13/18 · micro 12/16 · ตัวเลข hero 44/52 700 · summary-num 20/28 700
- **การ์ด**: พื้นขาว, `border-slate-200`, radius 16, เงาบาง `0 1px 2px rgba(15,23,42,.04)`
- **Component ที่มีแล้ว ใช้ซ้ำได้**: Toast (แถบ slate-900 ลอยล่างกลาง), ConfirmDialog (วงกลมไอคอน + 2 ปุ่ม), Drawer ขวา 440px (header 64 / footer ปุ่มติดล่าง), segmented control (track slate-100), chip (h-36 / h-32), skeleton pulse, EmptyState (ไอคอนในวงกลม 56 + หัวข้อ + CTA)

## 2. ข้อมูลที่มี

**Installment (จาก `/installments/list`)**
```json
{
  "installmentsId": 7,
  "installmentsName": "ผ่อนโทรศัพท์",
  "description": "iPhone 16",
  "totalAmount": 36000.00,
  "interestRate": 0.0,
  "interestType": "YEARLY",          // YEARLY | MONTHLY
  "calculationMethod": "FLAT",       // FLAT (คงที่) | EFFECTIVE (ลดต้นลดดอก)
  "installmentMonths": 10,
  "monthlyAmount": 3600.00,
  "startDate": "2026-05-25",
  "paidPeriods": "1,2,3,4",          // งวดที่จ่ายแล้ว
  "status": "ACTIVE",                // ACTIVE | CLOSED
  "closedAt": null
}
```

**ค่าที่คำนวณฝั่ง frontend อยู่แล้ว**
- ตารางงวด: งวดที่ · วันครบกำหนด · ค่างวด · เงินต้นคงเหลือ · สถานะ (จ่ายแล้ว / ถึงกำหนด-ยังไม่จ่าย / ยังไม่ถึงกำหนด)
- ต่อรายการ: งวดที่ถึงกำหนด, จ่ายแล้ว, เหลืออีก
- ภาพรวม (เฉพาะที่กำลังผ่อน): ยอดต้องจ่ายทั้งหมด, ต้องจ่ายเดือนนี้, **ค้างชำระ** (ครบกำหนดก่อนเดือนนี้แต่ยังไม่จ่าย), ต้องจ่ายเดือนหน้า, จ่ายไปแล้ว, เหลือที่ต้องจ่าย, % ที่จ่ายแล้ว
- Preview ตอนสร้าง/แก้ไข: ยอดผ่อนต่อเดือน, ดอกเบี้ยรวม, ยอดรวมที่ต้องจ่าย, ตารางจำลองทุกงวด

**พฤติกรรมสำคัญ**
- กด "จ่ายงวดนี้" → backend สร้างรายจ่ายในประวัติธุรกรรมอัตโนมัติ (ลงวันที่วันที่จ่าย) · ยกเลิกจ่าย → ลบรายจ่ายนั้น
- งวดที่ยังไม่ถึงกำหนด → กดจ่ายไม่ได้
- "ปิดยอด" → ย้ายไปกลุ่ม "ผ่อนเสร็จแล้ว" (status CLOSED) และแก้ไขไม่ได้อีก
- จ่ายครบทุกงวด → ย้ายไป "ผ่อนเสร็จแล้ว" อัตโนมัติ (ยังแก้ไขได้)
- ลบ = ซ่อนรายการ
- หน้า Dashboard ส่ง `focusId` มาได้ → หน้านี้ต้องเปิดรายการนั้นและเลื่อนไปหา (ต้องมี state "ไฮไลต์รายการที่ถูกเปิดมา")

## 3. หน้าปัจจุบัน

1. หัวข้อ "ตารางผ่อนชำระ"
2. **การ์ดสรุป 5 ช่อง** (ต้องจ่ายทั้งหมด / เดือนนี้ + ค้างชำระ / เดือนหน้า / จ่ายแล้ว / เหลือ) + progress bar
3. **รายการที่กำลังผ่อน** (แบ่งหน้า 10) — การ์ดขอบสีเหลือง กดเพื่อกาง:
   - หัวการ์ด: ชื่อ, วันเริ่ม, ค่างวด/เดือน, ปุ่ม "ปิดยอด" (แดงทึบ), ✏️, 🗑️
   - แถบล่าง: ยอดจัด, badge วิธีคิด, ดอกเบี้ย
   - กางแล้ว: progress bar + 3 กล่อง (ถึงกำหนด / จ่ายแล้ว / เหลือ) + ตารางงวดพร้อมปุ่มสถานะในแต่ละแถว
4. **ผ่อนเสร็จแล้ว** — กล่องพับได้ ตารางรายการ + badge "ปิดยอด" / "ครบแล้ว"
5. **Modal สร้าง/แก้ไข** กว้าง max-w-5xl: ฟอร์มซ้าย (ชื่อ, ยอดจัด, ดอกเบี้ย + ต่อปี/ต่อเดือน, จำนวนงวด, วิธีคิด Flat/Effective, วันเริ่ม, รายละเอียด, กล่องสรุป, ปุ่มบันทึก) · ขวาเป็นตารางจำลอง

### ปัญหา
- สไตล์เก่า (radius 3xl/2rem, ไอคอนนำหน้า label ทุกช่อง, `font-black`) ไม่เข้ากับ 2 หน้าที่ทำใหม่
- การ์ดสรุป 5 ช่องน้ำหนักเท่ากันหมด — ไม่รู้ว่าอะไรสำคัญ ("ค้างชำระ" ซึ่งสำคัญที่สุดถูกซ่อนเป็นบรรทัดเล็ก)
- การ์ดรายการไม่บอกความคืบหน้าจนกว่าจะกาง · ไม่บอก "งวดถัดไปเมื่อไหร่ / ค้างกี่งวด"
- ปุ่ม "ปิดยอด" แดงทึบอยู่ทุกการ์ด ดูอันตรายและรก
- ตารางงวดยาว ปุ่มสถานะ 3 แบบดูคล้ายกัน แยกงวดที่ต้องจ่ายตอนนี้ไม่ออก
- Loading / empty เป็นแค่ข้อความ

## 4. สิ่งที่ต้องการให้ออกแบบ

### 4.1 สรุปภาพรวม
- จัดลำดับความสำคัญ: **ต้องจ่ายเดือนนี้** เด่นที่สุด, **ค้างชำระ** เป็น alert สี expense/warn ชัดเจน (แสดงเมื่อ > 0)
- รอง: เดือนหน้า · จ่ายแล้ว · เหลือที่ต้องจ่าย · ยอดทั้งหมด
- progress bar % ที่จ่ายแล้ว

### 4.2 การ์ดรายการที่กำลังผ่อน (ยุบ)
- ชื่อ + รายละเอียดย่อ · ค่างวด/เดือน (ตัวเลขเด่น) · **progress ในตัวการ์ด** (จ่ายแล้ว x/y งวด)
- **งวดถัดไป**: วันที่ + ยอด · ถ้าค้าง → badge "ค้าง n งวด"
- ข้อมูลรอง: ยอดจัด · ดอกเบี้ย % (ต่อปี/เดือน) · วิธีคิด (chip)
- action: แก้ไข / ลบ / ปิดยอด → รวมในเมนู ⋯ หรือ icon button ที่ไม่ตะโกน (ปิดยอด ≠ ปุ่มแดงทึบ)
- สถานะไฮไลต์เมื่อถูกเปิดมาจาก Dashboard

### 4.3 การ์ดกางออก (รายละเอียด + ตารางงวด)
- สรุป 3 ค่า (ถึงกำหนด / จ่ายแล้ว / เหลือ) แบบกระชับ
- ตารางงวด: งวด · วันครบกำหนด · ค่างวด · เงินต้นคงเหลือ · สถานะ/action
  - 3 สถานะต้องแยกชัด: **จ่ายแล้ว** (เขียว, กดเพื่อยกเลิกได้) · **ถึงกำหนด–ยังไม่จ่าย** (ปุ่มหลัก "จ่ายงวดนี้", ถ้าเลยเดือนให้มีป้าย "ค้าง") · **ยังไม่ถึงกำหนด** (เทา, disabled)
  - แถวงวดปัจจุบัน/งวดถัดไปควรเด่น
  - กำลังบันทึก (loading ในปุ่มของแถวนั้น)
- พิจารณาว่าควรเป็น **กางในที่** (แบบเดิม) หรือ **drawer ขวา** แบบหน้าประวัติ — เสนอพร้อมเหตุผล

### 4.4 ผ่อนเสร็จแล้ว
- section พับได้ + จำนวน
- แถวรายการ: ชื่อ · badge "ครบแล้ว" (income) / "ปิดยอด" (พร้อมวันที่ปิด และ จ่ายแล้ว x/y) · ยอดจัด · ค่างวด · จำนวนงวด · วันเริ่ม
- action: แก้ไข (เฉพาะที่ไม่ใช่ CLOSED) · ลบ

### 4.5 สร้าง / แก้ไขรายการผ่อน
- เสนอรูปแบบ: modal กว้าง 2 คอลัมน์ (เดิม) หรือ drawer/หน้าเต็ม — ต้องเห็น **preview ตารางจำลองไปพร้อมกับกรอก**
- ฟิลด์: ชื่อ* · ยอดจัด/เงินต้น* (ช่องเงินตัวใหญ่แบบ AmountInput, format คอมมา) · อัตราดอกเบี้ย + ต่อปี/ต่อเดือน (segmented) · จำนวนงวด* · วิธีคิด FLAT/EFFECTIVE (segmented พร้อมคำอธิบายสั้น) · วันเริ่มชำระงวดแรก* · รายละเอียด (ไม่บังคับ)
- กล่องสรุปสด: **ยอดผ่อนต่อเดือน (เด่น)** · ดอกเบี้ยรวม · ยอดรวมที่ต้องจ่าย
- โหมดแก้ไข: แจ้งเตือนว่า "ระบบจะคำนวณตารางใหม่ งวดที่จ่ายเกินช่วงใหม่จะถูกตัดออก"
- validation inline (ยอด ≤ 0, งวด ≤ 0) · ปุ่มบันทึก disabled จนกว่าจะคำนวณได้

### 4.6 Dialog ยืนยัน (ปรับหน้าตาให้เข้า ConfirmDialog)
- จ่ายงวด: ชื่อ · งวด x/y · วันครบกำหนด · ค่างวด · หมายเหตุ "จะเพิ่มรายจ่ายในประวัติธุรกรรม"
- ยกเลิกจ่าย: หมายเหตุ "จะลบรายจ่ายของงวดนี้"
- ปิดยอด (danger): จ่ายแล้ว x/y · ค่างวดคงเหลือ
- ลบ (danger): ยอดจัด · จำนวนงวด (จ่ายแล้ว n)
- บันทึก/แก้ไข: สรุปข้อมูลทั้งหมด + ยอดผ่อนต่อเดือน

### 4.7 States
- loading (skeleton การ์ด)
- empty: ยังไม่มีรายการผ่อนเลย (CTA "เพิ่มรายการผ่อนแรก") / ไม่มีที่กำลังผ่อน (มีแต่ที่เสร็จแล้ว)
- ค้างชำระ (การ์ดและสรุป)
- การ์ดที่ถูกเปิดมาจาก Dashboard (ไฮไลต์)
- form preview ว่าง (ยังกรอกไม่ครบ)
- toast สำเร็จ / ผิดพลาด
- pagination เลขหน้า (เมื่อเกิน 10 รายการ)

## 5. สิ่งที่อยากได้กลับมา

1. Mockup desktop 1280 (มี sidebar 288px) — หน้าหลัก, การ์ดกางออก, ฟอร์มสร้าง/แก้ไข
2. States ตามข้อ 4.7 และ dialog ตามข้อ 4.6
3. Spec component ใหม่ (InstallmentCard, PeriodRow/StatusPill, SummaryHero, InstallmentForm) โดยอ้างอิง token เดิม
4. HTML/React + Tailwind ใช้ token ชุดเดิม (export ได้เหมือนรอบก่อน)
5. ถ้ามีจุดที่ต้องเปลี่ยน flow หรือ API — **แยกไว้เป็น "ข้อเสนอเพิ่มเติม"** ไม่ใส่ในดีไซน์หลัก
