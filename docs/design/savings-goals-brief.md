# Design Brief — ฟีเจอร์ "เงินออม" (Savings Goals)

> ฟีเจอร์ใหม่: แยกเงินบางส่วนออกจากเงินใช้ได้ไปเก็บใน "กระปุก" ตามเป้าหมาย (หลายเป้าได้) และทุบออกมาใช้ได้
> ต่างจากรอบก่อน — **รอบนี้เป็นฟีเจอร์ใหม่ ต้องมี backend ใหม่** (ตาราง + API ตามข้อ 3)
> อ้างอิง design system: `docs/design/transactions-redesign-brief.md`, `docs/design/installments-redesign-brief.md` และโค้ดใน `components/ui/*`, `components/installments/*`

---

## 0. ข้อกำหนดสำคัญ (อ่านก่อน)

- **เงินออม = การย้ายเงิน ไม่ใช่รายจ่าย**
  - ฝาก → เงินใช้ได้ลดลง แต่ **ไม่นับเป็นรายจ่าย** ในรายงาน/กราฟหมวดหมู่
  - ถ้านับฝากเป็นรายจ่าย แล้วทุบออกมาซื้อของอีก = นับรายจ่ายซ้ำ 2 รอบ
- **หลายเป้าหมาย** — ผู้ใช้สร้างกระปุกได้หลายใบ (เช่น "เที่ยวญี่ปุ่น", "เงินสำรองฉุกเฉิน")
- **ถอนได้ 2 แบบ**
  1. **ถอนกลับเข้ากระเป๋า** — เงินกลับมาเป็นเงินใช้ได้ ยังไม่ใช่รายจ่าย
  2. **ถอนไปใช้เลย** — เลือกหมวดหมู่รายจ่าย → ระบบสร้างรายจ่ายในประวัติธุรกรรมอัตโนมัติ (ลงวันที่ถอน) เหมือน flow จ่ายงวดผ่อน
- ใช้ design system ชุดเดิม ไม่สร้างสไตล์ใหม่ · Desktop เป็นหลัก แต่ไม่พังที่จอแคบ · ไม่ต้องทำ bottom nav
- เพิ่มเมนูใน Sidebar: **"เงินออม"** (ต่อจาก "ตารางผ่อนชำระ", ไอคอนแนะนำ `PiggyBank` จาก lucide)

## 1. สูตรเงิน

```
เงินออมในกระปุก   = Σ ฝาก − Σ ถอน (ทั้ง 2 แบบ)            ต่อกระปุก
เงินออมรวม        = Σ เงินออมทุกกระปุก
เงินใช้ได้         = รายรับ − รายจ่าย − Σ ฝาก + Σ ถอน (ทั้ง 2 แบบ)
ออมสุทธิเดือนนี้    = ฝากเดือนนี้ − ถอนเดือนนี้
อัตราการออม       = ออมสุทธิเดือนนี้ ÷ รายรับเดือนนี้
```

> ทำไม "ถอนไปใช้" ถึงบวกกลับในเงินใช้ได้: เพราะรายจ่ายที่ระบบสร้างจะถูกลบออกจากเงินใช้ได้อยู่แล้ว ผลสุทธิคือเงินใช้ได้ไม่เปลี่ยน — เงินออกจากกระปุกตรง ๆ

ตัวอย่าง (เดือนเดียว): รายรับ 30,000 · ฝากกระปุกญี่ปุ่น 5,000 · จ่ายค่ากิน 8,000 · ถอนจากกระปุกไปซื้อตั๋ว 3,000
- รายจ่ายเดือนนี้ = 8,000 + 3,000 = **11,000** (ตั๋วนับครั้งเดียว)
- กระปุกญี่ปุ่น = 5,000 − 3,000 = **2,000**
- เงินใช้ได้ = 30,000 − 11,000 − 5,000 + 3,000 = **17,000**

## 2. กฎทางธุรกิจ

- ฝาก: ยอด > 0 · ถ้ายอดฝากเกินเงินใช้ได้ → **เตือน** (ไม่บล็อก เพราะแอปยังไม่มียอดยกมา/ยอดเปิดบัญชี)
- ถอน: ยอด > 0 และ **≤ ยอดในกระปุก** (บล็อก)
- ถอนไปใช้: ต้องเลือกหมวดหมู่ประเภท EXPENSE · รายจ่ายที่สร้างลิงก์กลับไปที่รายการถอน
  - ลบรายการถอน → ลบรายจ่ายนั้นด้วย (เหมือนยกเลิกจ่ายงวด)
  - ในหน้าประวัติ รายจ่ายนี้มี badge "จากเงินออม · ชื่อกระปุก" และ **แก้ยอด/ลบจากหน้าประวัติไม่ได้** ให้ไปจัดการที่หน้าเงินออม (กันยอดกระปุกเพี้ยน)
- ฝาก/ถอนลงวันที่ย้อนหลังได้ · แก้ไข/ลบรายการฝาก-ถอนได้ (ลบ = soft delete)
- เป้าหมาย: ยอดเป้า **ไม่บังคับ** (บางกระปุกเก็บไปเรื่อย ๆ) · วันที่อยากถึงเป้า ไม่บังคับ
- ถึงเป้าแล้ว → แสดงสถานะ "ถึงเป้าแล้ว 🎉" แต่ยังฝาก/ถอนต่อได้
- **ปิดกระปุก** (เก็บเข้าคลัง): ต้องมียอดเป็น 0 ก่อน → ใน dialog มีทางลัด "ถอนทั้งหมดกลับเข้ากระเป๋า แล้วปิด"
- **ลบกระปุก**: ทำได้เมื่อยอดเป็น 0 เท่านั้น

## 3. ข้อมูล / Backend ที่ต้องเพิ่ม

แยกตารางใหม่ — **ไม่ใส่ลง `transactions`** เพราะ `TransactionService` / `DashboardService` แยกแค่ INCOME/EXPENSE (และรหัสธุรกรรมใช้หลักแรกเป็นประเภท 1/2) ถ้าเพิ่ม type ที่สามจะกระทบหลายจุด

**`savings_goal`**
| คอลัมน์ | ชนิด | หมายเหตุ |
|---|---|---|
| savings_goal_id | bigserial PK | |
| user_id | FK users | |
| name | varchar | บังคับ |
| target_amount | numeric(14,2) | null = ไม่มีเป้า |
| target_date | date | null ได้ |
| icon | varchar | key ไอคอน (ชุดเดียวกับ categoryIcons) |
| color | varchar | key สีจาก palette ที่กำหนด |
| status | varchar | `ACTIVE` \| `ARCHIVED` |
| created_at, archived_at, is_deleted | | |

**`savings_movement`**
| คอลัมน์ | ชนิด | หมายเหตุ |
|---|---|---|
| savings_movement_id | bigserial PK | |
| savings_goal_id | FK | |
| user_id | FK | |
| type | varchar | `DEPOSIT` \| `WITHDRAW` |
| amount | numeric(14,2) | > 0 เสมอ |
| movement_date | timestamp | |
| note | varchar | null ได้ |
| transaction_id | bigint | มีค่าเฉพาะ "ถอนไปใช้" → ลิงก์รายจ่ายที่สร้าง |
| is_deleted | boolean | |

**`transactions`** เพิ่ม `savings_movement_id` (nullable) — ใช้แสดง badge และกันแก้ไขในหน้าประวัติ (แบบเดียวกับ `installments_id`)

**API (เสนอ, POST + userId ใน body ตาม pattern เดิม)**
- `/savings/list` → กระปุกทั้งหมด + `balance`, `depositedThisMonth`, `progress` (คำนวณฝั่ง backend)
- `/savings/create` · `/savings/update` · `/savings/archive` · `/savings/delete`
- `/savings/movements` → ประวัติฝาก-ถอนของกระปุก (แบ่งหน้า)
- `/savings/deposit` · `/savings/withdraw` (`mode`: `TO_WALLET` | `SPEND`, + `categoryId` เมื่อ SPEND)
- `/savings/movement/update` · `/savings/movement/delete`
- `/dashboard/summary` เพิ่ม: `savingsTotal`, `savingsNetThisMonth`, `savingsRate`, `availableBalance`

**ตัวอย่าง response `/savings/list`**

```json
  "balance": 18500.00,

  "progress": 0.308,
  "suggestedMonthly": 6917.00     // (เป้า − ยอด) ÷ เดือนที่เหลือ, null ถ้าไม่มีวันที่
}
```

## 4. สิ่งที่ต้องการให้ออกแบบ

### 4.1 หน้า "เงินออม" — สรุปด้านบน
- **เงินออมรวม** (ตัวเลข hero 44/52)
- รอง: ออมสุทธิเดือนนี้ · อัตราการออม % · เงินใช้ได้ (ให้เห็นว่าย้ายเงินมาจากไหน)
- ปุ่มหลัก: "+ สร้างกระปุก"

### 4.2 การ์ดกระปุก (grid 2–3 คอลัมน์)
- ไอคอน + สีของกระปุก · ชื่อ
- **ยอดในกระปุก** (เด่น) / เป้า · progress bar (ถ้าไม่มีเป้า → ไม่มี bar แสดง "ไม่กำหนดเป้า")
- บรรทัดรอง: "ต้องออมเดือนละ ~฿x เพื่อถึงเป้าใน dd MMM yy" หรือ "ถึงเป้าแล้ว 🎉" หรือ "เลยกำหนดแล้ว" (warn)
- เดือนนี้ฝากไป ฿x
- action ในการ์ด: **ฝาก** (ปุ่มหลัก) · **ถอน** (ปุ่มรอง) · เมนู ⋯ (แก้ไข / ปิดกระปุก / ลบ)
- คลิกการ์ด → เปิดรายละเอียด (ข้อ 4.4)

### 4.3 Sheet ฝาก / ถอน (drawer ขวา 440px หรือ dialog — เสนอพร้อมเหตุผล)
- **ฝาก**: กระปุก (preselect) · ยอด (AmountInput ตัวใหญ่) · ปุ่มลัดยอด (+500 / +1,000 / ถึงเป้า) · วันที่ · หมายเหตุ
  - แสดง "เงินใช้ได้หลังฝาก ฿x" สด · ถ้าติดลบ → เตือนสี warn
- **ถอน**: segmented 2 แบบ
  - **กลับเข้ากระเป๋า** — คำอธิบายสั้น "ยังไม่นับเป็นรายจ่าย"
  - **ใช้จ่ายเลย** — แสดงช่องเลือกหมวดหมู่รายจ่าย (chip grid แบบ TxnForm) + คำอธิบาย "จะเพิ่มรายจ่ายในประวัติธุรกรรม"
  - ยอด (มีปุ่ม "ถอนทั้งหมด") · วันที่ · หมายเหตุ
  - แสดง "คงเหลือในกระปุก ฿x" สด · เกินยอด → error inline + ปุ่ม disabled

### 4.4 รายละเอียดกระปุก (drawer ขวา หรือหน้าย่อย — เสนอ)
- หัว: ไอคอน · ชื่อ · ยอด/เป้า · progress · วันที่เป้า
- กราฟเล็ก: ยอดสะสมรายเดือน (เส้น/แท่ง 6–12 เดือนล่าสุด) — optional
- **ประวัติฝาก-ถอน**: วันที่ · ประเภท (ฝาก = brand/income tone, ถอนกลับกระเป๋า = slate, ถอนไปใช้ = expense + ชื่อหมวด) · ยอด (+/−) · หมายเหตุ · ⋯ แก้ไข/ลบ
- ปุ่ม ฝาก / ถอน ติดล่าง

### 4.5 สร้าง / แก้ไขกระปุก
- ชื่อ* · ยอดเป้า (ไม่บังคับ, toggle "ไม่กำหนดเป้า") · วันที่อยากถึงเป้า (ไม่บังคับ) · เลือกไอคอน · เลือกสี (6–8 สีจาก palette ที่เข้ากับ token)
- preview การ์ดสด + "ต้องออมเดือนละ ~฿x"
- โหมดสร้าง: ช่อง "ฝากครั้งแรก" (ไม่บังคับ)

### 4.6 กระปุกที่ปิดแล้ว
- section พับได้ + จำนวน · แถว: ชื่อ · ยอดเป้า · วันที่ปิด · ยอดที่เคยออมสูงสุด (ถ้าทำได้) · action: เปิดใช้อีกครั้ง / ลบ

### 4.7 จุดที่กระทบหน้าอื่น
- **Dashboard**
  - การ์ด KPI "คงเหลือสุทธิ" → เปลี่ยนเป็น **"เงินใช้ได้"** (sub: "รายรับ − รายจ่าย − ออมสุทธิ") หรือเพิ่มการ์ดใหม่ — เสนอ
  - เพิ่ม widget "เงินออม": เงินออมรวม · ออมเดือนนี้ · อัตราการออม · กระปุก top 3 พร้อม progress (คลิก → หน้าเงินออม focus กระปุกนั้น)
  - กราฟ "รายจ่ายแยกหมวด" ไม่เปลี่ยน (เงินฝากไม่อยู่ในนี้)
- **ประวัติธุรกรรม / TxnRow**: รายจ่ายจากการถอนไปใช้ → badge "จากเงินออม · ชื่อกระปุก" · drawer แก้ไขแสดงข้อความ "จัดการที่หน้าเงินออม" + ลิงก์ แทนปุ่มแก้ไข/ลบ
- **บันทึกรายการ**: ไม่เปลี่ยน (ฝาก/ถอนทำที่หน้าเงินออมเท่านั้น)

### 4.8 Dialog ยืนยัน (ใช้ ConfirmDialog)
- ฝาก: กระปุก · ยอด · เงินใช้ได้หลังฝาก
- ถอนกลับกระเป๋า: กระปุก · ยอด · คงเหลือในกระปุก
- ถอนไปใช้: + หมวดหมู่ · หมายเหตุ "จะเพิ่มรายจ่าย ฿x ในประวัติธุรกรรม"
- ลบรายการถอนไปใช้ (danger): "จะลบรายจ่ายที่ผูกอยู่ด้วย"
- ปิดกระปุก: ถ้ายอด > 0 → ทางเลือก "ถอนทั้งหมด ฿x กลับเข้ากระเป๋า แล้วปิด"
- ลบกระปุก (danger): ทำได้เมื่อยอด = 0

### 4.9 States
- loading (skeleton การ์ด)
- empty: ยังไม่มีกระปุก → EmptyState + CTA "สร้างกระปุกแรก" + ตัวอย่างเป้าหมาย (เที่ยว / ฉุกเฉิน / ของชิ้นใหญ่)
- กระปุกยอด 0 · ไม่มีเป้า · ถึงเป้าแล้ว · เลยวันที่เป้า
- ฝากเกินเงินใช้ได้ (warn) · ถอนเกินยอด (error)
- กระปุกที่ถูกเปิดมาจาก Dashboard (ไฮไลต์)
- toast สำเร็จ / ผิดพลาด
